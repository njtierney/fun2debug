Welcome

Welcome to Functions and Debugging! This course will teach you how to write your own functions and confidently debug your R code.

Details

I would argue the highest value skillset in statistical programming is knowing how to write good functions. Functions are often taught as a tool to avoid repetition using the mnemonic DRY: Don’t Repeat Yourself. Whilst DRY is both true and real, I think functions are at their best when they encapsulate expression and are easy to reason with. That is, DRY is sufficient, but not necessary.

Writing good functions is more than esoteric aesthetics. We need to be able to reason with our code in statistics. We often don’t have the capacity to write tests to show our code is “correct”. Instead, we need to rely on our ability to reason with, trust, and verify that the code works as it should. I believe writing good functions that encapsulate expressions and are able to be reasoned with are how we can ensure our code, and therefore our methods, and our analyses, work as they should.

This course is for people writing analysis code, not packages. You will take a real analysis script, ideally your own, and turn it into a set of named, documented functions that you can look inside when something goes wrong, and reason about when it doesn’t. The functions you end up with are the same unit of work that pipelines like targets are built from, so this is useful whether or not you ever write a pipeline.

Prerequisites

  • Basic R programming experience
  • Familiarity with R scripts and basic data manipulation
  • Experience running R code and encountering errors
  • An analysis script of your own that you would like to improve

Learning outcomes

  • Write functions to express an idea.
  • Spot when code has become expensive to re-read
  • Recognise the reasons to (and not to!) write a function
  • Design a function from the outside in, before writing its body
  • Extract a function out of code you have already got working
  • Name functions and arguments so they explain themselves
  • Document a function with roxygen, so you and others know how to use it
  • Read an R error message and work out where it actually came from
  • Use debugging tools: browser(), debug() and debugonce() to look inside a running function
  • Turn a long analysis script into a set of functions without breaking it
  • Efficiently, and fairly measure code speed.
